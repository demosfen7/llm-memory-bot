# Telegram-бот с долговременной памятью LLM

## Описание задания

Учебный проект к домашнему заданию по теме «Краткосрочная и долгосрочная память LLM».
В проекте два Telegram-бота на одной и той же модели OpenAI:

- `bot_no_memory.py` — бот без памяти: каждый вопрос уходит в модель сам по себе;
- `bot_memory.py` — бот с долговременной памятью: история диалога и краткое резюме
  пользователя хранятся в SQLite и переживают перезапуск.

Сравнив их ответы на одни и те же сообщения, видно, что модель сама по себе ничего не помнит:
«память» — это то, что программа заново кладёт в каждый запрос.

## Чем отличаются боты

| | `bot_no_memory.py` | `bot_memory.py` |
|---|---|---|
| Что уходит в модель | системный промпт + текущее сообщение | системный промпт с резюме + последние 10 сообщений |
| Где хранится история | нигде | SQLite (`memory.db`) |
| После перезапуска | всё забыто | история и резюме на месте |
| Команды | `/start` | `/start`, `/reset` |

## Как работает память

**Краткосрочная память** — это контекст в рамках текущего запроса. Модель видит только то,
что передано в `messages` одного вызова Chat Completions API. У `bot_no_memory.py` там лишь
одно сообщение, у `bot_memory.py` — последние 10 сообщений диалога. Больше 10 не передаём,
чтобы не раздувать контекст и стоимость запроса.

**Долгосрочная память** — это SQLite-база из двух таблиц:

- `messages` — все сообщения пользователя и ответы ассистента;
- `user_context` — краткое резюме о пользователе (имя, предпочтения, цели, важные факты).

После каждых 10 сообщений пользователя бот отправляет модели последний отрезок диалога
и прежнее резюме и просит обновить резюме (не длиннее 500 символов). Резюме попадает в
системный промпт, поэтому бот помнит ключевые факты, даже когда они давно выпали из
последних 10 сообщений.

Порядок обработки сообщения в `bot_memory.py`:

1. Сохранить сообщение пользователя в SQLite.
2. Загрузить последние 10 сообщений (новое — последнее из них).
3. Загрузить резюме из `user_context`.
4. Собрать системный промпт с резюме.
5. Отправить в модель системный промпт и историю.
6. Сохранить ответ ассистента в SQLite.
7. Отправить ответ пользователю, затем при необходимости обновить резюме.

**Загрузка истории после перезапуска.** Бот ничего не держит в оперативной памяти: на каждое
сообщение он читает историю из `memory.db`. Поэтому после перезапуска `bot_memory.py`
разговор продолжается с того же места.

**Очистка памяти.** Команда `/reset` удаляет все сообщения и резюме только того пользователя,
который её отправил, и отвечает: «Память очищена. Начинаем с чистого листа.»

## Установка

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate  # macOS/Linux
# .venv\Scripts\activate   # Windows

pip install -r requirements.txt
cp .env.example .env
```

В Windows PowerShell вместо `cp` используйте `Copy-Item .env.example .env`.

Затем откройте `.env` и впишите настоящие значения:

```env
TELEGRAM_BOT_TOKEN=токен от BotFather
OPENAI_API_KEY=ключ OpenAI
OPENAI_MODEL=gpt-4o-mini
DATABASE_PATH=memory.db
```

`OPENAI_MODEL` и `DATABASE_PATH` можно не менять. Относительный `DATABASE_PATH`
считается от папки проекта.

## Как получить токен Telegram-бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`.
3. Введите отображаемое имя бота, затем username, который заканчивается на `bot`
   (например, `viktor_memory_test_bot`).
4. BotFather пришлёт токен вида `123456789:AA...`. Скопируйте его в `TELEGRAM_BOT_TOKEN`.

Один токен нельзя одновременно использовать в двух запущенных программах: Telegram вернёт
ошибку `Conflict`. Поэтому либо запускайте ботов по очереди, либо создайте у BotFather
двух ботов и держите две копии папки с разными `.env`.

## Как получить OpenAI API key

1. Войдите на [platform.openai.com](https://platform.openai.com/).
2. Пополните баланс в разделе Billing: без него API отвечает ошибкой лимита.
3. Откройте [API keys](https://platform.openai.com/api-keys) и нажмите
   «Create new secret key».
4. Скопируйте ключ (он показывается один раз) в `OPENAI_API_KEY`.

## Запуск бота без памяти

```bash
python bot_no_memory.py
```

## Запуск бота с памятью

```bash
python bot_memory.py
```

Остановка — `Ctrl+C`. В консоли видны все сообщения пользователей и ответы бота.
Токены и ключи в лог не выводятся.

## Тестовые сценарии

1. Запустите `bot_no_memory.py` и напишите боту: «Меня зовут Виктор».
2. Спросите: «Как меня зовут?» — бот без памяти не знает.
3. Остановите его, запустите `bot_memory.py` и повторите оба сообщения — бот отвечает «Виктор».
4. Сравните ответы двух ботов.
5. Перезапустите `bot_memory.py` (`Ctrl+C`, затем снова `python bot_memory.py`).
6. Снова спросите: «Как меня зовут?» — бот должен вспомнить имя.
7. Отправьте `/reset`.
8. Снова спросите: «Как меня зовут?» — бот должен ответить, что не знает.

Чтобы проверить резюме, отправьте боту с памятью 10 сообщений с фактами о себе. В консоли
появится строка `Резюме user=... обновлено: ...`, а содержимое можно посмотреть в базе:

```bash
sqlite3 memory.db "SELECT * FROM user_context;"
```

## Примеры ожидаемых ответов

Бот без памяти:

```text
Вы: Меня зовут Виктор
Бот: Приятно познакомиться, Виктор! Чем могу помочь?
Вы: Как меня зовут?
Бот: Я не знаю, как вас зовут: я не вижу предыдущих сообщений. Можете напомнить?
```

Бот с памятью:

```text
Вы: Меня зовут Виктор
Бот: Приятно познакомиться, Виктор! Чем могу помочь?
Вы: Как меня зовут?
Бот: Вас зовут Виктор.

(перезапуск bot_memory.py)

Вы: Как меня зовут?
Бот: Вас зовут Виктор.
Вы: /reset
Бот: Память очищена. Начинаем с чистого листа.
Вы: Как меня зовут?
Бот: Я пока не знаю вашего имени. Как к вам обращаться?
```

Точные формулировки зависят от модели, но смысл ответов должен быть таким.

## Безопасность

Файлы `.env` (токен бота и ключ OpenAI) и `memory.db` (личные сообщения пользователей)
не должны попадать в публичный репозиторий. Оба уже перечислены в `.gitignore`.
Если ключ всё же утёк, сразу отзовите его: токен — командой `/revoke` у BotFather,
ключ OpenAI — на странице API keys.
